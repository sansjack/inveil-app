# Contract v1

The wire contract between the Inveil client and a backend. The Rust types in [`crates/contract`](../../crates/contract/src) are the source of truth.

| File | Status |
|---|---|
| [`openapi.yaml`](openapi.yaml) | Hand-written OpenAPI 3.1 for `/v1/rules`, `/v1/usage` and `/v1/enroll`, plus the update manifest schema. |
| `Snapshot`, `UpdateManifest`, `SignedEnvelope`, `EnrollRequest`, `EnrollResponse`, `UsageBatch` `.schema.json` | JSON Schema generated from the Rust types. `cargo test -p contract schema` fails when a committed file differs from what the types produce; `UPDATE_SCHEMAS=1 cargo test -p contract schema` rewrites them. Do not edit them by hand. |
| [`vectors/`](vectors) | Signed good and deliberately broken envelopes, plus `manifest.json` stating the key, signing domain, threshold and expected outcome of each. Generated by `crates/engine/tests/vectors.rs`; `UPDATE_VECTORS=1 cargo test -p engine --test vectors` rewrites them. The signing keys are test keys derived from public seeds. |

Read [docs/CONTRACT.md](../../docs/CONTRACT.md) for the signing rules and versioning policy. If `openapi.yaml` and the Rust types disagree, the Rust types win; please open an issue.
